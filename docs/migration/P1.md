# P1 — Resultados y validación veraces

Fecha: 2026-09-06. Estado: contención del flujo legado implementada y validada; no acredita generación de productos.

## Componentes modificados

- registry/harness: los 13 agentes académicos quedan identificados como legacy y no se ejecutan por el harness. Se conservan funciones e IDs porque hay referencias activas y valor documental, pero no se presenta contenido fijo como trabajo real. Una decisión needs_user_input ya no permite continuar la función.
- validators/schemas: evidencia resoluble con hash del contenido consumido, rechazo de números no finitos, exceso de tokens y gates obligatorios sin verificador. No se afirma consistencia/cobertura por flags del productor.
- context: el hash corresponde al texto efectivamente consumido después del truncado.
- orchestrator/reports/cli: cierre derivado de resultados, manifiesto de hashes, verificación de formato e integridad, retorno no cero ante fallo, verify sin escritura. Los runs académicos sin manifiesto se consideran legados no certificables y permanecen intactos.
- observability: distingue estimaciones locales de uso de modelo. No cuenta allowlists como herramientas ejecutadas.

## Archivos movidos

Ninguno. Dependencias revisadas: cli → orchestrator/harness; harness → agents/registry/policy/context/memory/validators; tests importan interfaces existentes. Se agrega reports sin cambiar ubicación de los módulos.

## Archivos eliminados

Ninguno. Se reemplazó la lógica de cierre estática y se retiraron ramas que aprobaban controles sin verificarlos. Las funciones documentales antiguas se mantienen inaccesibles desde el flujo público normal para no romper referencias antes de su sustitución por generadores.

## Archivos creados

factory/reports.py, tests/test_integrity.py, este registro.

## Decisiones tomadas

Bloquear explícitamente el bootstrap legado es preferible a ejecutarlo con claims falsos. La fábrica aún no tiene un workflow de producto que pueda terminar complete. Los gates no implementados fallan de forma cerrada; un validador semántico no se simula. El manifiesto detecta corrupción o alteración parcial, pero no prueba autenticidad frente a alguien que reescriba conjuntamente todos los archivos.

## Pruebas ejecutadas

Suite completa: 24 passed, 0.17 s, mediante el comando de P0. Incluye evidencia ficticia, hash manipulado, seis gates no implementados, límites de tokens, NaN, catálogo legado, cierre de fallo, alteración del final-report y códigos CLI. Imports del núcleo se cargan en la suite. python3 -B -m factory.cli --help sigue iniciando (también se comprueba al cierre).

## Errores encontrados

No fallos en la suite de esta fase. Los tests originales no detectaban la falsa aceptación: se agregaron escenarios negativos reales. Los reportes históricos no tienen formato de integridad nuevo; su verificación no se promueve a éxito.

## Problemas pendientes

El cuerpo de las funciones académicas sigue siendo material legado, no código apto para ejecutar sobre clientes. Ejecutor aislado, almacenamiento atómico y límites efectivos de procesos corresponden a P2. Nuevos generadores reemplazarán funciones según P3, pendiente del brief concreto que el usuario decidió enviar. No se marca aprobada la arquitectura o seguridad por el solo hecho de pasar tests.
