# P3.3 — Base visual corporate-site v0.1.0

P3.1/P3.2 fueron aprobadas explícitamente por el usuario. Esta entrega implementa solo P3.3. No inicia P3.4, generador, funcionalidades interactivas de negocio, módulos ni deployment.

## Implementación

Base independiente en templates/corporate-site con Next.js App Router, TypeScript, React, CSS Modules y tokens. Componentes: CorporateSite, Header, Footer, Hero, About, Plans, Services, FAQ, Contact y DemoPanels. La única página de contenido es /. Next agrega su página técnica de no encontrado.

La configuración pública sintética reside en src/content/site.json. La proyección pública del piloto está en config/pilots/nexonova/visual-content.json. No contiene WorkOrder, hashes privados, autorización o estado de la fábrica. SiteContent tipa los props; los componentes no tienen condiciones de cliente. Se usa una sustitución explícita del JSON únicamente en copias temporales para validar las dos configuraciones; no se implementó el generador determinista ni se creó nexonova-website.

Los precios de ejemplo están solo en configuración piloto. El template general no tiene planes comerciales por defecto. El texto español compartido corresponde al recorrido aprobado del MVP es-CL, no a prestaciones comerciales. La proyección visual es un contrato de presentación interno; no reemplaza corporate-site.v0.1.0 ni concede autorización. La integración automática contrato → generador sigue pendiente.

FAQ y menú móvil usan details/summary nativos, enlaces ancla y foco visible. Dominios, asistente y Tu consulta tienen estructura y controles inactivos explícitos: no hay consultas, mensajes, preparación/copia, persistencia, formularios enviados o contratación. Esos comportamientos no se adelantan desde P3.4.

## Dependencias y entorno

Next 15.5.25 conserva la familia 15 del prototipo sin reutilizar su rango antiguo; React/ReactDOM 19.2.8, TypeScript 5.9.3 y tipos fijados. Node probado 22.22.1, npm 9.2.0. Lockfile v3 con integridad. La combinación se verifica mediante instalación/build, no por suposición. La revisión operativa de vulnerabilidades sigue siendo responsabilidad de mantenimiento.

Referencia primaria para actualización: [release de seguridad Next de agosto](https://nextjs.org/blog/august-2026-security-release). Compatibilidad base: [documentación de instalación](https://nextjs.org/docs/app/getting-started/installation).

Playwright 1.63.0 es dependencia SOLO de desarrollo para responsive, teclado, errores de navegador y solicitudes externas. No biblioteca UI adicional. No auth, BD, Route Handlers, analytics, fuentes remotas ni conexiones de negocio.

La preparación npm usa HOME temporal, userconfig=/dev/null y --ignore-scripts --no-audit --no-fund. El acceso al registro/CDN es exclusivamente preparación de herramientas. Build y servidor usan código nuevo revisado; no se ejecutan scripts del prototipo. Esto es validación manual autorizada por el operador, no prueba de que el executor Python P2 ya soporte Node. Un adaptador web restringido continúa pendiente y no se declara implementado.

## Errores encontrados

- Primer intento Python: 135 aprobadas, 1 error de cuota de disco (Errno 122) al escribir metadata temporal. No se modificó runtime ni test.
- Intento TMPDIR dentro del checkout: 71 aprobadas, 4 fallos y 61 errores; el control de almacenamiento rechazó correctamente esa ubicación. Error de configuración de esta validación, conservado en P3_3_FACTORY_TESTS_BAD_TMPDIR.txt.
- Con TMPDIR externo en /var/tmp: 136 pruebas aprobadas en 20.16s, sin cambios de restricciones.
- Primera descarga Chromium: error de escritura por cuota de /tmp. Se conserva salida completa y se prepara headless en /var/tmp, sin instalar paquetes del sistema.
- Un npm --package-lock-only se lanzó accidentalmente en raíz y creó un lockfile vacío. Se verificó y eliminó únicamente ese archivo nuevo; la fábrica no se convirtió en proyecto npm.
